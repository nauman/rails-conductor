01 · Client Access and Managed Billing

One organization can host several clients. Membership grants limit operational visibility; one client wallet funds managed backups and fixed shared-app or dedicated-server capacity.

Commercial vertical slice

Access

Owners see all. Editors and members choose all or selected grants, bounded by any linked client account. Role still controls capability.

Wallet

Stripe Checkout funds an immutable Conductor ledger through verified, idempotent webhooks.

Managed services

Backups use operation/GB-month rates. Hosting uses fixed app-month or server-month rates.

Access evaluation

flowchart LR
  A[Authenticated membership] --> C{Inside organization and client boundary?}
  C -->|No| D[Deny]
  C -->|Yes| R{Role capability allows action?}
  R -->|No| D[Deny]
  R -->|Yes| S{resource_scope}
  S -->|all| O[Allow organization resource]
  S -->|selected| G{Direct app grant or server inheritance?}
  G -->|No| D
  G -->|Yes| O

An app grant never reveals the whole server. Staff may receive shared-server grants; a client-linked server grant requires a same-client dedicated server.

Money and failure flow

flowchart LR
  C[Stripe Checkout] --> W[Verified webhook]
  W --> T[Immutable top-up entry]
  B[Successful backup] --> U[Pending usage fact + consumed reservation]
  M[Monthly hosting event] --> P[Snapshot effective client rate]
  P --> U2[Idempotent usage event]
  U --> L[Retry-safe immutable debit + settled reservation]
  U2 --> L
  T --> X[Derived client balance]
  L --> X
  X --> G{Balance minus reservations within grace?}
  G -->|Yes| RUN[Reserve and allow variable operation]
  G -->|No| HOLD[Persist hold + alert client and admin]

Credit exhaustion never stops an existing app, destroys data, or revokes dashboard access. Service suspension is manual and deferred.
